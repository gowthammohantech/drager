# ADR-014: Pairing transcript binds HELLO wire bytes; canonical JSON profile

Status: Accepted

## Context
Today `PairingTranscript.hash()` re-encodes the decoded HELLO messages with `ControlMessageCoder`. It does not hash the bytes that crossed the wire. Two peers therefore derive the same SAS and keys only if every implementation re-encodes byte for byte the way Swift's `JSONEncoder` does.

Swift's encoder also drops unknown fields, so a HELLO from a newer peer would hash differently on each side. Kotlin and .NET serializers differ from Swift's by default:
- `System.Text.Json` escapes non-ASCII characters and `+<>&`.
- `android.util.Base64.DEFAULT` wraps lines.

## Decision
1. **Hash the bytes as they crossed the wire.** The transcript absorbs the exact payload of each HELLO frame: the bytes this side sent for its own HELLO, and the bytes it received for the peer's.
   - `SessionChannel` exposes the received payload next to the decoded message.
   - For Swift peers, the wire bytes equal the old re-encoding, so new Apple builds still pair with old ones.
2. **All implementations still emit canonical JSON** (`docs/API/CONFORMANCE.md`): sorted keys, compact, `/` not escaped, non-ASCII as raw UTF-8, padded base64 without line breaks, dates as integer milliseconds, nil optionals omitted.
   - The `canonical-json` vectors define the exact escape set.

## Consequences
- JSON quirks in one implementation can no longer split the SAS between peers.
- Canonical output still matters for readable diffs, for the vectors, and for talking to Apple builds released before this ADR.
- The label order of the transcript is unchanged.
