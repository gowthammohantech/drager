# ADR-010: Pairing: SAS-authenticated X25519, sessions over TLS 1.3 external PSK

Status: Accepted

## Context
FRD §5 requires authenticated key exchange with an out-of-band short code and encrypted sessions, without custom primitives or permissive trust callbacks.

## Decision
First contact runs over plain TCP: HELLO ↔ HELLO, PAIR_REQUEST (X25519 ephemeral + Ed25519 key + challenge) → PAIR_RESPONSE (same + transcript signature). Both sides derive SAS/PSK/confirm keys with HKDF-SHA256 salted by the transcript hash. Users compare a 6-digit SAS; each side sends PAIR_CONFIRM (HMAC over role and approved peer; the initiator also signs the transcript). Trust is persisted only when the local user approved and the peer's confirmation verified. Failures are rate-limited (3 per 60 s). Subsequent sessions use TLS 1.3 with the 32-byte pair PSK (`sec_protocol_options_add_pre_shared_key`, identity = initiator peer ID); the listener registers one PSK per trusted peer and an unknown identity fails the handshake (T-11).

## Consequences
The SAS is never key material. A MITM must guess the SAS (1 in 10⁶ per attempt, rate-limited).
