# ADR-011: Interrupted transfers restart; resume is P1

Status: Accepted

## Context
AD §7: resume needs authenticated state revalidation.

## Decision
On disconnect, cancel or hash mismatch the receiver deletes the staging `.sbpart` file and records a terminal outcome. The sender surfaces a Retry action (automatic up to 2 times for retryable errors, then manual) that **reuses the same transfer ID**. The receiver's ledger answers a committed ID with the recorded COMMITTED and processes a failed ID afresh. One user activation therefore yields at most one saved file even if the COMMITTED message was lost (PRD §2, FR-108). Offsets and PROGRESS acks are already on the wire so resume can be added without a protocol bump. Stale staging files older than 24 h are purged at launch.

## Consequences
Large transfers over flaky Wi-Fi restart from zero.
