# ADR-017: Rename the product to Drager

Status: Accepted (supersedes the bundle IDs in ADR-009)

## Context
The product ships to the App Store as "Drager". No App Store Connect record existed under the old bundle ID, so this was the last free moment to change identifiers.

## Decision
- The user-facing name is **Drager** on every platform: display names, UI copy, notifications, privacy strings, the Windows package manifest, the website and the current docs.
- Bundle and package IDs:
  - iOS: `com.gowthammohan.drager.ios`
  - macOS: `com.gowthammohan.drager.mac`
  - Android `applicationId`: `com.gowthammohan.drager.android`
  - Windows package identity: `Drager.Receiver`
- Keychain service names and access groups follow the new bundle IDs.
- Unchanged:
  - Code identifiers: repo folders, Xcode projects, `SpatialBridgeKit`, Kotlin `com.spatialbridge.*` packages and C# `SpatialBridge.*` namespaces.
  - The Bonjour service type `_spatialbridge._tcp`, because it is a wire contract shared by all four platforms.
  - The conformance vector message `"Spatial Bridge ed25519 vector"`, because changing it would change the published vectors.
  - The read-only requirement docs and earlier ADRs.

## Consequences
- Test installs under the old IDs are separate apps, with separate keychain items. Remove them and pair again.
- Renaming the code identifiers can follow later as a mechanical refactor with no user-visible effect.
